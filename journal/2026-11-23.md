- Auth spike: the `accounts` plugin reads `Authorization: Bearer <token>` and answers 401 to linkding's `Token <token>` (GAP-034). With Bearer, `:protect` gives each caller their own `root`, so the fixed token on `root.shared` was not needed. The bridge turns `Token` into `Bearer` (marked `WORKAROUND(GAP-034)`). What M6 must replace: that keyword rewrite; tokens that are stable per user and several per user (accounts make a new token at each login); linkding's user fields (`is_staff`, names: GAP-027); a way to read the caller's username.
- `@restspec` cannot carry `/api/`: GET and POST only, exact paths, a function with no parameters and no documented way to read the request, 200 or 500 as the only statuses (GAP-030 to GAP-033, each shown with a run). The second approach worked: a `transport` plugin written from the docs (`plugins/rest_bridge`, about 200 lines on `http.server`) passes every request under `/api/` to one app endpoint (`rest.handle`, or `rest.handle_public` for a request with no credentials) and sends back the status and body it returns. It stands in for the whole standard transport (GAP-037) and had to print the `listening on` line itself (GAP-036).
- The REST layer is Jac in `app/` (`rest*.jac`, layer `rest`); integer ids come from `ids.jac`; the search expression language is `search_expression.jac` (its own slice). Dates leave as `YYYY-MM-DDTHH:MM:SS.ffffffZ` as the original writes them, from naive UTC kept in nodes (the GAP-029 workaround holds). `tools/check_persistence.sh` now saves through `/api/`, restarts the binary and reads back with the same token: ok. `neojac test` 41 tests; `check`, `fmt --check` and `arch` clean.
